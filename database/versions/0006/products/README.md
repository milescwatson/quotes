# Regular products and quote multiples (0006)

Apply after verified migration 0005. This additive migration creates the organization-scoped regular product catalog and adds a quote multiple defaulting to 1.0000. Existing quote lines, customer metadata, ownership, timestamps, and concurrency tokens must remain unchanged. A bounded backfill sets existing null multiples to 1 without changing quote metadata; no quote JSON backfill is needed: absent line kind means configured, and absent line multiple means 1.

Regular products have independent list prices and optional links to configured parents. Runtime permissions allow SELECT/INSERT/UPDATE and sequence usage; DELETE remains denied. Authorization stays in the service: organization members read, Administrators and Super Administrators write. Parent sharing checks apply when assigning or changing a parent; an unchanged unavailable parent remains linked.

Quote lines store snapshots for configured, regular, and freeform sources. Catalog changes affect newly added regular lines, while saved regular lines retain their snapshots. Freeform lines never create catalog entries. Unit price and line total remain list amounts. Adjusted line total is list line total × quote multiple × line multiple, rounded half-up once to cents; quote adjusted total sums these rounded line amounts. Multiples accept 0–1000 with up to four decimal places through the API. The database stores four decimal places and constrains the quote multiple range. USD money remains limited to 12 integer digits and two fractional digits, with aggregate overflow checked by the service.

## Coordinated release procedure

1. Confirm the target environment/account/cluster and verify its 0005 schema and grants against the deployment ledger. Source availability does not imply applied state. Record the current quote count and a digest of IDs, lines, customer/project, owner, modifier, modification timestamp, and existing catalog state. Confirm `regular_products` and `quotes.multiple` are absent; inspect any partially applied state before proceeding.
2. Save the API's current reserved concurrency, pause writes using the established development release procedure, and drain in-flight requests for the configured Lambda timeout plus the established safety margin. Keep the application paused until both the API and frontend release have been verified.
3. Apply each statement in `schema.sql` in its own transaction as the schema operator. Journal the statement text/hash, completion, and any DSQL asynchronous job IDs; wait for each asynchronous job to complete. Repeat `backfill.sql` in bounded batches until no null quote multiples remain; apply `enforce.sql` and await its asynchronous validation job. Apply `permissions.sql` after replacing `:"api_role"` with the target runtime role. Do not rerun earlier migrations or blindly replay a partial 0006 installation.
4. Verify the new table, organization/parent foreign keys, unique part number constraint, price/range checks, sequence grants, quote multiple default/range, and denied runtime DELETE. Compare the original quote digest and count; confirm all existing quote multiples equal 1.0000. Record verified migration evidence in the deployment ledger.
5. Release the matching API bundle and updated OpenAPI Gateway contract, then the frontend generated from that contract. Use the existing environment release tooling; do not use the fixed 0004 or 0005 installers to apply 0006.
6. Under the actual runtime IAM role, verify catalog create/edit/read, duplicate/stale edit errors, Sales read/write restrictions, shared parent selection, mixed quote creation, compound/zero multiples, rounding, no-op save, and snapshot preservation after a catalog edit. Use dedicated temporary fixtures and remove or roll back only those fixtures. Perform a browser smoke test for regular/freeform addition and quote save/reload.
7. Restore the saved concurrency only after matching database/API/frontend verification. Journal restoration and release versions. If validation fails, keep writes paused, investigate the incomplete step, and retain the additive schema. An older API cannot safely edit mixed regular/freeform quotes; do not restore an old writer after new-format quotes have been accepted.

Use `node server/scripts/deploy-products-database.mjs inventory` for read-only preflight and `node server/scripts/deploy-products-database.mjs apply` for checkpointed development migration. The apply mode leaves the API paused until the coordinated release and verification complete.

## Local verification

Run `npm test` in `database` and `server`. Server integration fixtures install 0006 after 0004 and the current organization migration. Run `npm run typecheck`, `npm run build`, and `npm run test:e2e -- tests/quote-editor.spec.ts` in `app`. Browser scenarios use isolated session-storage fixtures; these do not substitute for actual DSQL/runtime-role verification at release time.
